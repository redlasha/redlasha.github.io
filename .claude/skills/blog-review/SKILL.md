# 블로그 초안 리뷰

**메인 세션에서 직접 리뷰하지 않는다.** 초안을 쓴 컨텍스트가 그대로 남아 있으면 자기 글의 오류가 잘 안 보인다. 반드시 서브에이전트에 맡긴다.

## 서브에이전트 호출

Agent 툴로 `general-purpose` 에이전트를 띄우고, 아래를 포함한 프롬프트를 준다.

### 반드시 넣을 것

1. **초안 파일의 절대 경로**
2. **대조할 공식 문서 URL 목록** — 초안이 인용한 문서 전부. WebFetch로 직접 읽으라고 명시
3. **검증할 주장을 항목별로 나열** — 수치, 기본값, 플래그명, 동작 조건. "글의 주장을 검증해줘"로 뭉뚱그리지 말고 하나씩 적는다
4. **파일을 수정하지 말 것** — 리뷰만 하고 보고하게 한다
5. **확신도를 표시할 것** — 확신 낮은 지적도 포함하되 표시하게 한다

### 리뷰 항목

프롬프트에 아래 순서로 요청한다.

| 순서 | 항목 | 요구사항 |
|---|---|---|
| 1 | 사실 오류 / 부정확 | 심각도 순. 원문 인용 + 정확한 내용 + 근거 문서 |
| 2 | 근거 부족한 단정 | 출처 불분명한 주장, 과장 부사 |
| 3 | 구성 개선 | 우선순위 순. 섹션 순서, 늘어지는 곳 |
| 4 | 누락 | 공식 문서엔 있는데 빠진 임팩트 큰 내용 |
| 5 | 문장 | 번역투, 반복, 톤 불일치 |
| 6 | 총평 | 발행 가능한지, 아니면 무엇부터 고칠지 |

**"솔직하게, 좋게 포장하지 말고"를 명시한다.**

## 결과 처리

리뷰가 돌아오면 그대로 적용하지 말고 판단한다.

- **사실 오류** → 공식 문서를 다시 확인하고 수정. 리뷰어가 틀렸을 수도 있다
- **구성 제안** → 글의 분량과 목적에 비춰 취사선택. 전부 반영하면 글이 불어난다
- **누락 지적** → 정말 필요한지 본다. 완결성보다 초점이 중요하다

사용자에게 보고할 때는 **무엇을 반영했고 무엇을 왜 안 했는지** 함께 말한다.

## 자주 잡히는 것

경험상 이 유형이 반복해서 나온다.

- **비율·배수 표현의 방향 역전** — "A 대비 B"가 의도와 반대로 읽히는 경우
- **목록의 누락** — "이게 전부"인 것처럼 제시했는데 공식 문서엔 항목이 더 있는 경우
- **수사적 과장이 만드는 자기모순** — 강한 문장이 다른 섹션의 주장과 충돌
- **문제만 제기하고 해법을 안 준 곳** — 공식 문서에 대응책이 있는데 빠뜨림

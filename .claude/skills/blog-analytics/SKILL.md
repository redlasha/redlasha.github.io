# 측정

`_ops/ANALYTICS.md`를 먼저 읽는다. **지난번에 세운 가설이 무엇이었는지** 확인하고 시작한다. 가설 없이 숫자만 보면 아무 결론도 안 나온다.

## 도구

| 도구 | 접근 | 용도 |
|---|---|---|
| GA4 (`G-05MZM203YG`) | 브라우저 | 유입 경로, 참여 시간, 재방문 |
| Clarity (`xuz8z7kqs2`) | 브라우저 | 스크롤 깊이, 히트맵, 세션 녹화 |
| Search Console | 브라우저 | 검색 질의, 노출/클릭 |

전부 로그인이 필요한 대시보드다. **브라우저 도구로 직접 열어 확인한다.** 사용자에게 화면을 요청해도 된다.

## 볼 것 — 넷만 본다

`STRATEGY.md`의 성공 기준과 1:1로 대응한다. 이 밖의 지표는 재미로 보는 것이고 판단에 쓰지 않는다.

| 기준 | 지표 |
|---|---|
| 끝까지 읽히는가 | 스크롤 깊이, 평균 참여 시간 |
| 다시 오는가 | 재방문 비율, **시리즈 간 이동률** |
| 발견되는가 | 검색 질의, 유입 채널 |
| 무엇이 통했나 | 글별 참여 시간 비교 |

**시리즈 간 이동률이 이 블로그의 핵심 지표다.** 상호 링크를 건 이유이고, 시리즈가 자산인지 판별한다.

## 기록 형식 — 관찰과 해석을 분리한다

```markdown
### YYYY-MM-DD — <한 줄 요약>

**관찰**: (숫자와 사실만. 해석 금지)

**해석**: (관찰에서 무엇을 읽는가. 확신도를 표시)

**액션**: (무엇을 할 것인가. 없으면 "없음"이라고 쓴다)

**다음 확인**: (날짜와 검증할 가설)
| 가설 | 확인 방법 |
```

섞어 쓰면 나중에 검증이 안 된다. "체류시간 3분"은 관찰이고 "목차가 효과 있었다"는 해석이다.

## 해석할 때 주의

- **초기 데이터는 노이즈가 크다.** 유입이 적을 때 비율 지표는 몇 명으로 요동친다. 주 단위로 보고 일 단위로 반응하지 않는다
- **공유 트래픽을 분리한다.** GeekNews 등에 올린 직후 유입은 평상시 지표를 왜곡한다
- **상관을 인과로 읽지 않는다.** 목차를 넣은 주에 체류시간이 늘었다고 목차 때문이라고 단정할 수 없다. 다른 변경이 함께 있었는지 본다
- **Clarity는 production에서만 로드된다.** 로컬 방문은 안 잡힌다

## 액션으로 잇기

지표가 판단을 바꿀 만하면 다음으로 넘긴다.

| 발견 | 다음 |
|---|---|
| 특정 주제가 잘 읽힘 | `/blog-plan` — 시리즈 확장 검토 |
| 특정 지점에서 이탈 | `/blog-design` 또는 글 구조 수정 |
| 예상 밖 검색 질의 유입 | `IDEAS.md`에 글감 추가 |
| 가설이 반증됨 | `/blog-plan` 모드 B — 전략 점검 |

**"데이터를 봤다"로 끝내지 않는다.** 액션이 없으면 없다고 명시적으로 쓴다.

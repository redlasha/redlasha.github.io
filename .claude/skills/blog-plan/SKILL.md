# 기획

`_ops/STRATEGY.md`, `_ops/EDITORIAL.md`, `IDEAS.md`를 먼저 읽는다. 없는 상태에서 새로 만들지 말고 **기존 판단을 이어받아 갱신한다.**

## 두 가지 모드

### A. 다음 글 정하기 (자주)

1. `IDEAS.md`의 후보를 훑는다
2. 각 후보를 아래로 평가한다

| 기준 | 질문 |
|---|---|
| 전략 부합 | 포지셔닝(운영·관측·최적화)에 맞나 |
| 고유성 | 내가 아니면 못 쓰는 글인가. 직접 겪은 문제에서 나왔나 |
| 준비도 | 지금 쓸 수 있나, 실측·조사가 선행돼야 하나 |
| 시리즈 | 앞 글의 결론을 재료로 쓰는가 |

3. **고유성이 가장 중요하다.** 남도 쓸 수 있는 글은 순위를 낮춘다
4. 정해지면 `EDITORIAL.md`의 "다음에 쓸 것" 갱신 → `/blog-draft` 제안

### B. 전략 점검 (분기 1회, 또는 신호 발생 시)

`STRATEGY.md`의 "재검토 시점"에 해당하는 일이 생겼을 때.

1. `_ops/ANALYTICS.md`의 관찰 로그를 읽는다 — **가설이 맞았나**
2. 필요하면 `/blog-research`로 시장 재조사
3. 포지셔닝·독자·성공 기준을 조정
4. **변경한 이유를 `_ops/DECISIONS.md`에 남긴다**

## 원칙

- **측정 없이 전략을 바꾸지 않는다.** "느낌상 반응이 없다"는 근거가 아니다. `ANALYTICS.md`를 먼저 본다
- **목적을 도달 지표로 바꾸지 않는다.** 기록이 1차 목적이고 도달은 결과다. 이 순서가 뒤집히면 글이 얕아진다
- **계획을 늘리지 않는다.** 후보를 100개 쌓는 것보다 다음 하나를 정하는 게 낫다
- 완벽주의가 발행을 막는 주범이다. 준비가 덜 된 본편보다 **지금 쓸 수 있는 짧은 글**이 낫다

## 산출물

| 모드 | 갱신 파일 |
|---|---|
| A | `_ops/EDITORIAL.md` |
| B | `_ops/STRATEGY.md`, `_ops/DECISIONS.md` |

변경 후 사용자에게 **무엇이 왜 바뀌었는지** 요약해 보고한다.

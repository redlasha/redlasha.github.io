# 조사

**조사는 반드시 문서로 남는다.** 세션은 초기화되지만 판단의 근거는 남아야 한다.

산출물: `_ops/research/YYYY-MM-DD-<주제>.md`

## 조사 유형

| 유형 | 묻는 것 |
|---|---|
| **지형 조사** | 이 주제를 누가, 어떤 각도로 쓰고 있나. 비어 있는 자리는 어디인가 |
| **주제 검증** | 이 글감이 실제로 수요가 있나. 이미 잘 답해진 질문인가 |
| **채널 조사** | 어디에 공유해야 도달하나 |
| **기법 조사** | SEO/GEO, 조판, 도구 등 운영 기법 |

## 방법

1. **범위는 WebSearch, 근거는 WebFetch.** 검색 요약만 보고 결론 내지 않는다. 중요한 주장은 원문을 직접 읽는다
2. **공식 문서가 있으면 1차 출처로 삼는다.** 블로그·미디엄은 2차
3. **한국어와 영어를 모두 검색한다.** 국내 지형과 글로벌 동향이 다르다
4. **정량 데이터가 없으면 없다고 쓴다.** "검색 상위 콘텐츠의 유형 분류"와 "시장 점유율"은 다르다

## 문서 형식

```markdown
# <주제> 조사

조사일: YYYY-MM-DD
방법: (무엇을 어떻게 봤는지. 데이터의 한계를 여기 적는다)

## 발견 (번호를 붙여 나눈다)

## 그래서 무엇을 할 것인가
| 판단 | 근거 |

## 검증되지 않은 가정 (다음 조사 과제)
- [ ] …

### 출처
```

**"검증되지 않은 가정" 절을 반드시 넣는다.** 조사의 가치는 확인한 것만큼이나 확인 못 한 걸 아는 데 있다.

## 규칙

- **`_ops/research/`는 append-only.** 기존 문서를 수정하지 않는다. 판단이 바뀌면 새 날짜로 새 문서를 쓰고, 옛 문서에 링크를 건다
- 조사 결과가 전략에 영향을 주면 `/blog-plan`을 제안한다
- 조사가 글감을 낳으면 `IDEAS.md`에 추가한다

## 하지 말 것

- 검색 결과 요약을 그대로 옮기기. 유형화하고 해석해야 조사다
- 근거 없이 시장 규모나 수요를 단정하기
- 자기 가설에 유리한 것만 담기. **가설을 반증하는 증거를 적극적으로 찾는다**

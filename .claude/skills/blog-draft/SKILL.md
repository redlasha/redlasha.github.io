# 블로그 초안 작성

`CLAUDE.md`의 작성 규칙을 먼저 읽고 따른다.

## 순서를 지킬 것

주제를 받으면 **바로 쓰지 말고** 아래 순서로 간다. 개요를 먼저 상세히 잡으면 자료조사 시간이 줄고 글의 흐름이 일관된다.

### 1. 리서치 — 공식 문서 우선

- **공식 문서를 1차 출처로 삼는다.** Claude Code면 `code.claude.com/docs`, API면 `platform.claude.com/docs`
- 블로그·미디엄 글은 2차 출처다. 공식 문서와 어긋나면 공식 문서를 따른다
- WebSearch로 범위를 잡고, WebFetch로 원문을 직접 읽는다. 검색 요약만 보고 쓰지 않는다
- 확인한 사실과 확인 못 한 주장을 분리해 기록한다

### 2. 개요 — 초안 전에 사용자에게 보여준다

다음을 먼저 정하고 확인받는다.

- **한 문장 후크**: 글 전체를 압축한 `>` 인용구
- **독자가 가져갈 것 2~3개**
- **섹션 구조**: H2 목록과 각 섹션의 핵심 주장
- **어떤 사실이 근거로 필요한가**: 아직 확인 안 된 게 있으면 여기서 드러난다

### 3. 초안 작성

- 도입부는 **구체적인 경험이나 장면**에서 출발한다. 일반론으로 시작하지 않는다
- 개념 → 그로부터 연역되는 실천 순서로 배치한다. 팁 나열이 아니라 하나의 관점으로 묶는다
- 반직관적인 사실을 앞에 둔다. 독자가 이미 아는 걸 뒤에 둔다
- 표는 열거 가능한 짧은 사실에만. 설명은 산문으로
- 마지막은 "하나만 가져간다면" 형태로 압축

## 하지 말 것

- 근거 없이 단정하기. 공식 문서가 "can be"면 "될 수 있다"로 쓴다
- 출처 없는 "일반적으로", "많은 사람들이", "커뮤니티에서는" — 1인칭 경험으로 바꾸거나 뺀다
- 본문에 H1 쓰기 (`CLAUDE.md` 참조)
- 확인하지 않은 수치·버전·플래그명 적기

## 산출물

`_posts/YYYY-MM-DD-slug.md`가 아니라 **먼저 스크래치패드에 쓴다.** 리뷰를 통과한 뒤 `/blog-publish`가 `_posts/`로 옮긴다.

front matter는 초안 단계에서 채워둔다 — `title`, `excerpt`, `date`, `categories`, `tags`.

## 다음 단계

초안이 끝나면 사용자에게 `/blog-review`를 제안한다. 팩트체크 없이 발행하지 않는다.

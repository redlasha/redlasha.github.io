## 목적

**AI 코딩 에이전트를 실제로 굴리며 겪은 문제와 그 구조적 이유를 기록한다.**

기록이 1차 목적이다. 도달은 그 결과지 목표가 아니다. 이 순서가 뒤집히면 글이 얕아진다.

## 포지셔닝

> AI 코딩 에이전트를 프로덕션처럼 운영하면서 관측·최적화한 기록

**경쟁 공백이 확인된 자리다.** 국내 Claude Code 콘텐츠는 설치·사용법 / 도입 후기 / 도구 비교 세 유형이고, 셋 다 "쓰기 시작하는 사람"을 향한다. 이미 쓰고 있는 사람이 겪는 운영 문제를 다루는 한국어 콘텐츠는 검색 상위에 없다.

**단, 경쟁이 없다는 게 수요가 있다는 뜻은 아니다.** 이 가설은 측정으로 검증한다.

## 독자

**주 독자**: Claude Code를 이미 매일 쓰고 있고, 한도·비용·구성 때문에 불편을 겪은 개발자

- 설치법을 설명할 필요 없다
- "왜 이렇게 되는가"에 관심이 있다
- 공식 문서를 읽을 줄 알지만 다 읽을 시간은 없다

**비독자**: 입문자, "AI로 개발이 어떻게 바뀌나" 같은 담론을 찾는 사람

## 차별점

| 축 | 이 블로그 | 대부분의 글 |
|---|---|---|
| 출처 | 공식 문서 1차 인용 | 경험담 또는 재전달 |
| 깊이 | 메커니즘에서 연역 | 팁 나열 |
| 검증 | 서브에이전트 팩트체크 | 없음 |
| 소재 | 직접 만든 도구에서 나온 문제 | 일반적 사용 경험 |

**가장 방어하기 어려운 자산은 마지막 줄이다.** 도구를 만들면서 겪은 문제는 남이 복제할 수 없다.

## 성공 기준

도달 지표를 1차 목표로 두지 않는다. 대신 이 순서로 본다.

| 순위 | 기준 | 측정 |
|---|---|---|
| 1 | 글이 정확한가 | 팩트체크 통과, 사후 정정 건수 |
| 2 | 끝까지 읽히는가 | 스크롤 깊이, 체류시간 |
| 3 | 다시 오는가 | 재방문 비율, 시리즈 간 이동률 |
| 4 | 발견되는가 | 검색 유입, AI 검색 인용 여부 |

4번을 맨 아래 둔 건 통제 불가능해서다. 1~3번은 통제 가능하고, 그게 되면 4번은 따라온다.

## 유통

| 채널 | 방식 | 상태 |
|---|---|---|
| GeekNews | 발행 후 수동 공유 | 검증된 채널, 미실행 |
| 검색 | 한국어 롱테일 질의 대응 | 제목·소제목에 반영 중 |
| AI 검색 (GEO) | 인용되기 쉬운 구조 유지 | 이미 유리한 형태 |

GEO는 별도 최적화 작업이라기보다 **정확성을 추구한 결과 얻어진 것**이다. 표, 자기완결적 문단, 질문형 소제목, 공식 문서 인용이 그대로 인용 확률을 높이는 요인과 겹친다. 이 방향을 유지하는 게 곧 GEO다.

## 시리즈

**Claude Code 운영 시리즈** (`claude-code` 태그)

```
1편 계정 — 관측 도구가 거짓말할 때
2편 토큰 — 캐시가 깨지는 지점
3편 계정 × 캐시 — 계정 경계는 캐시 경계다   ← 다음
```

각 편이 앞 편의 결론을 재료로 쓴다. 이 구조가 유지되는 한 시리즈는 자산이 된다.

## 재검토 시점

분기 1회, 또는 아래 중 하나가 발생할 때.

- 국내에 같은 포지션의 블로그가 등장
- 3편까지 발행 후 지표가 가설과 다름
- Claude Code 자체의 큰 변화로 소재 지형이 바뀜

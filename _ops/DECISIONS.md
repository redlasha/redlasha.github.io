# 결정 로그

되돌리거나 재논의할 때 필요한 것은 결정 자체가 아니라 **그때의 근거**다. 새 항목은 위에 추가한다.

---

## 2026-08-01 — 기존 글에 이미 있는 내용을 짧은 글로 떼어내지 않는다

**결정**: `/rewind`가 `/compact`보다 싼 이유, worktree마다 캐시가 따로 쌓인다 — 두 짧은 글 후보를 기각.

**근거**: 둘 다 2편 본문에 이미 들어 있다. 독립 글로 내면 자기 콘텐츠와 경쟁한다. 검색에서 같은 주제로 두 페이지가 나뉘면 각각의 신호가 약해지고, AI 검색 인용에서도 어느 쪽이 인용될지 갈린다. 준비도가 높다는 이유만으로 남겨두면 언젠가 쓰게 되므로 명시적으로 기각한다.

**적용 범위**: 앞으로도 "긴 글에서 한 조각 떼어내기"는 기본적으로 하지 않는다. 예외는 **떼어낸 쪽이 원문에서 다루지 않은 각도를 갖는 경우** — 3편에서 분리한 "한도별 대응 순서"가 그 예다. 3편은 계정 배분을 다루고, 그 글은 한도가 걸린 뒤의 대응 순서를 다룬다.

**되돌린다면**: 원문이 너무 길어져 특정 주제가 묻히는 게 확인되면 그때 분리를 재검토한다.

---

## 2026-08-01 — `_ops/`를 사이트에 게시하지 않는다

**결정**: 운영 문서를 저장소에 두되 Jekyll `exclude`로 게시에서 제외.

**근거**: 전략·지표·미해결 과제는 공개할 이유가 없다. 그렇다고 별도 저장소로 빼면 글과 함께 버전 관리되지 않아 시차가 생긴다. 같은 저장소 + 게시 제외가 절충안.

**되돌린다면**: 공개해도 무방하다고 판단되면 `_config.yml`의 `exclude`에서 빼면 된다.

---

## 2026-08-01 — 조판 보정을 SCSS가 아닌 `head/custom.html`에 넣는다

**결정**: CSS 오버라이드를 `<style>` 블록으로 head에 인라인.

**근거**: Gemfile이 없어 로컬 빌드 검증이 불가능한 상태다. SCSS 오류는 GitHub Pages 빌드를 통째로 실패시키는데, 실패를 미리 잡을 방법이 없다. `<style>` 블록은 빌드 단계를 거치지 않아 이 위험이 0이다.

**비용**: SCSS 변수(`$max-width` 등)를 못 쓰고 CSS 선택자로 덮어써야 한다. 테마가 크게 바뀌면 선택자가 깨질 수 있다.

**되돌린다면**: Gemfile을 추가해 로컬 빌드가 가능해지면 SCSS로 옮길 수 있다.

---

## 2026-08-01 — 본문 H1을 금지한다

**결정**: 모든 글에서 본문 H1 제거, `CLAUDE.md`에 규약으로 명시, `/blog-publish`에 검사 추가.

**근거**: 테마가 front matter `title`을 이미 H1으로 렌더링한다. 본문 H1은 ① 제목 중복 ② `excerpt_separator: "\n\n"` 때문에 **목록 발췌문이 제목 반복**이 되는 두 문제를 만들었다. 원인이 하나였다.

**교훈**: 기존 글이 전부 그렇게 돼 있으면 "관례"로 보이지만, 관례가 아니라 같은 버그가 반복된 것일 수 있다.

---

## 2026-08-01 — GitHub Actions 빌드 전환을 보류한다

**결정**: OG 이미지 자동 생성에 필요하지만 Phase 2로 미룸.

**근거**: GitHub Pages 기본 빌드는 `--safe` 모드라 화이트리스트 플러그인만 동작한다. Actions 빌드로 바꾸면 전부 열리지만, 전환 중 사이트가 잠시 안 뜰 수 있다. 발행 직후라 미루는 게 낫다고 판단.

**전제 조건**: 발행 직후가 아닌 시점, 되돌릴 절차 확인.

---

## 2026-08-01 — 포지셔닝을 "운영·관측·최적화"로 고정

**결정**: 입문/사용법이 아니라 이미 쓰는 사람의 운영 문제를 다룬다.

**근거**: [시장 조사](research/2026-08-01-market-landscape.md) — 국내 Claude Code 콘텐츠가 설치·사용법 / 도입 후기 / 도구 비교 세 유형에 몰려 있고 운영 각도는 비어 있음.

**위험**: 경쟁이 없는 게 수요가 없어서일 수 있다. 3편까지 발행 후 지표로 검증한다.
